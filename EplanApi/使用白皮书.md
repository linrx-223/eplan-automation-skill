# EPLAN 本地 API 使用白皮书（接入与操作手册）

> **适用对象**：想让 AI / 外部程序来操作你电脑上 EPLAN 的人。**不需要会写代码**。  
> **读法**：看「比喻」懂原理，看「能复制的命令」和「表格」直接操作。  
> **版本**：2026-10-03（订正 MCP 与服务的端口不一致、修正 MCP 章节引用与工具清单）；上一版 2026-09-24 全面修订（订正端口、目录名、加载方式；补全真实动作清单）。

## 1. 这东西是干嘛的（先用比喻懂原理）

可以把这套东西想成**三人协作**：

| 角色  | 是谁                        | 干什么                |
| --- | ------------------------- | ------------------ |
| 老板  | **你 / 其他 AI Agent**       | 下指令：“打开工程”“建个项目”   |
| 翻译官 | **本程序（EplanApi，端口 5000）** | 把指令翻译成 EPLAN 听得懂的话 |
| 工人  | **EPLAN 软件本身**            | 真正画图、建项目           |

但 EPLAN 这个“工人”有个怪脾气：**外人不能直接命令它**。所以我们又安排了一个**潜伏在 EPLAN 内部的联系人（AddIn，端口 5002）**，翻译官把活儿交给它，它就在 EPLAN 肚子里直接办。

```
你 / 其他 AI
    │  发请求
    ▼
[翻译官] EplanApi  →  端口 5000  →  POST /api/eplan/execute
    │  需要真画图时，转交
    ▼
[内部联系人] EplanAddin  →  端口 5002  →  http://127.0.0.1:5002/api/addin/
    │  在 EPLAN 进程内部直接调用 API
    ▼
[工人] EPLAN 软件  →  画图 / 建项目 / 导出
```

**一句话总结**：你只要对着「端口 5000」喊一句话（JSON），剩下的活儿程序自己分派，最终让 EPLAN 干活。

## 2. 启动前，先打勾这 4 件事

| # | 检查项               | 怎么确认                                             | 不对会怎样                 |                   |
| - | ----------------- | ------------------------------------------------ | --------------------- | ----------------- |
| ① | **.NET 10 运行时已装** | 打开 PowerShell 输入 `dotnet --version`，能看到 `10.x.x` | 服务起不来                 |                   |
| ② | **EPLAN 已安装**     | 文件 `D:/EPLAN/Platform/2.9.4/Bin/Eplan.exe` 存在    | 报“找不到 EPLAN”          |                   |
| ③ | **EPLAN 当前是开着的**  | 任务栏能看到 EPLAN 窗口                                  | AddIn（5002）没起来，建项目会失败 |                   |
| ④ | **端口 5000 没被占**   | PowerShell 输入 \`netstat -ano                     | findstr 5000\` 无输出    | 服务起不来（解决法见第 10 节） |

> 路径配置已帮你配好，在 `EplanApi/appsettings.json` 里：
>
> ```json
> "ExecutablePath": "D:/EPLAN/Platform/2.9.4/Bin/Eplan.exe",
> "ExtraArguments": "/Variant:\"Electric P8\"",
> "CloseAfterScript": false
> ```
>
> `CloseAfterScript: false` = 干完活**不会关掉**你的 EPLAN，放心。

>
> | 目录               | 状态                    | 监听地址                                         | 支持的动作                                                                                       | 证据                                                                                                              |
> | ---------------- | --------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
> | `EplanAddin/`    | **功能全，已实测跑通，正在用**     | `http://127.0.0.1:5002/api/addin/`           | Ping / CreateProject / CreatePages / DrawMainCircuit / DrawPlcIO / DrawLadder / OpenProject | 2026-10-04 引导加载后 Ping 返回 `addin alive`；`CreateProject` 实测成功，返回 `opened(Exclusive)`，项目已在 EPLAN 中打开               |
> | `EplanApiAddin/` | 功能少，**从未被 EPLAN 加载过** | `http://127.0.0.1:5002/`（注意没有 `/api/addin/`） | 仅 Ping（返回 `pong from AddIn`）/ CreateProject / OpenProject                                   | 其 DLL（9216 字节）拷在 `Bin\AddIns\` 放了一周多、EPLAN 多次重启，**5002 始终未监听**；且该版本一旦加载必写 `C:\Temp\eplan_addin.log`，而**该文件不存在** |

> **核心结论（推翻旧版说法）**：EPLAN 2.9.4 **不会自动扫描** `Bin\AddIns\`。丢在那里的 DLL 是“死文件”，重开 EPLAN 也不会生效。  
> 真正生效的，是经**引导脚本**从 `C:\Temp\EplanAddin\EplanApiAddin.dll`（完整版，**14336 字节**）加载起来的那个。
>
> 两个目录产出的 DLL 文件名都叫 `EplanApiAddin.dll`，极易混淆。**改代码前先确认改的是哪一个**——以 `EplanAddin/` 为准。
>
> **Ping 返回的文本就是版本判据**：`addin alive` = 完整版（对）；`pong from AddIn` = 简化版（错，需按第 4 节步骤 B 重新引导）。
>

>
> 📌 **2026-10-04 补充实测：两个必须知道的限制**
>
> **限制一：Insert 接口只能插宏，不能连线。**
> 用 `DrawAbbPanel` 在 `api接口测试` 工程插入 9 个宏后，数据文件变化如下：
>
> | 文件 | 插入前 | 插入后 | 含义 |
> | --- | --- | --- | --- |
> | `Page.eod` | 1,146 B | 2,292 B | 新页已建 |
> | `Function.eod` | 587,845 B | 1,175,690 B | 器件/功能已插入 |
> | `Instance.eod` | 901,925 B | 1,145,090 B | 图形符号已插入 |
> | `Connection.eod` | 1 B | **1 B** | ⚠️ **一根线都没连** |
>
> 所以「帮我把原理图画出来」这个需求，用现有动作只能做到**器件摆好、连线全无**。
> 需要真连线的话，得改 AddIn（把 `Insert` 换成逐个放符号 + 让 EPLAN 自动连接），属于新开发。
>
> **限制二：`DrawAbbPanel` 用独占模式打开工程，工程不能先在 EPLAN 里开着。**
> 若目标工程已开在 EPLAN GUI 中，会返回 `{"success":false,"error":"项目打不开(所有 OpenMode 都失败)"}`。
> **处理办法**：让用户在 EPLAN 里「项目 → 关闭」该工程（**EPLAN 主程序保持运行**，关了 5002 就没了），再重新调用即可成功（实测通过，日志显示 `opened(Exclusive); 新建页;`）。

## 4. 怎么启动（手把手，分步）

### 步骤 A：启动 Web 翻译官（端口 5000）

1. 打开 **PowerShell**。
2. 逐行复制粘贴（每行回车）：
   ```powershell
   cd D:\默认存储空间\EPLAN\EplanApi
   dotnet run
   ```
3. 看到这两行，就成功了，**这个窗口别关**：
   ```
   Now listening on: http://localhost:5000
   Application started. Press Ctrl+C to shut down.
   ```
4. 要停止：在这个窗口按 `Ctrl + C`。

### 步骤 B：让 EPLAN 内部的联系人（5002）上岗（★必须用引导命令）

⚠️ **不能靠"重开 EPLAN"**——EPLAN 不会自动扫描 `Bin\AddIns\`（2026-10-04 已实测确证）。必须用引导脚本把插件拉起来：

1. **先完全退出 EPLAN**（右上角关闭，记得保存项目）。
2. 在 PowerShell 里执行这一条，它会重新打开 EPLAN 并顺带加载插件：
   ```powershell
   Start-Process -FilePath "D:\EPLAN\Platform\2.9.4\Bin\Eplan.exe" `
     -ArgumentList '/Variant:"Electric P8"','ExecuteScript','/ScriptFile:"C:\Temp\EplanScripts\LoadAddIn.cs"'
   ```
3. EPLAN 打开后，验证 5002 是否上岗：
   ```powershell
   Invoke-RestMethod -Uri http://127.0.0.1:5002/api/addin/ -Method Post -ContentType "application/json" -Body '{"action":"Ping"}'
   ```
   返回 `{"success":true,"message":"addin alive"}` = **完整版上岗，成功**。

| 如果看到              | 说明      | 怎么办                                                                                            |
| ----------------- | ------- | ---------------------------------------------------------------------------------------------- |
| `addin alive`     | 完整版（对）  | 直接用，第 6 节全部动作可用                                                                                |
| `pong from AddIn` | 误加载了简化版 | 检查 `C:\Temp\EplanAddin\EplanApiAddin.dll` 是不是 14336 字节，不是就重新拷完整版                               |
| 连不上 / 超时          | 引导没跑成   | 看 `C:\Temp\addin_load_result.txt` 里的报错；或改用 `/Runscript:"C:\Temp\EplanScripts\LoadAddIn.cs"` 重试 |

> 💡 **引导脚本**在 `C:\Temp\EplanScripts\LoadAddIn.cs`，它加载的是 `C:\Temp\EplanAddin\EplanApiAddin.dll`（完整版，14336 字节）。  
> 以后改了 AddIn 代码：重新编译 → 先关 EPLAN（DLL 会被锁住）→ 把新 DLL 拷到 `C:\Temp\EplanAddin\` → 重跑上面第 2 步的引导命令。

## 5. 接口规则（给 Agent / 懂点技术的你）

### 5.1 统一入口

- **地址**：`http://localhost:5000/api/eplan/execute`
- **方法**：`POST`
- **内容类型**：`application/json`

### 5.2 请求体（你发的话）

```json
{
  "action": "动作名",
  "parameters": { "键": "值" }
}
```

- `action`：要 EPLAN 做什么（见第 6 节清单）。
- `parameters`：动作需要的参数；没有就写 `{}`。

### 5.3 返回体（程序回的话）

```json
{
  "success": true,
  "message": "执行结果说明",
  "error": null
}
```

- `success: true` = 成了，看 `message`。
- `success: false` = 失败，看 `error` 找原因（对照第 10 节）。

## 6. 支持的动作清单（共 8 个）

| action            | 用途                   | 必需参数               | 需要真实工程吗 | 走哪条通道                  |
| ----------------- | -------------------- | ------------------ | ------- | ---------------------- |
| `Ping`            | 自检：确认服务活着、链路通        | 无                  | 否       | Web 直接回，不碰 EPLAN       |
| `OpenProject`     | 打开一个 EPLAN 工程        | `path`=.elk 路径     | **是**   | 脚本桥接（EPLAN /Runscript） |
| `ExportPdf`       | 导出 PDF               | `path`             | **是**   | 脚本桥接（目前占位，未完全实现）       |
| `CreateProject`   | 新建「物流传输_三段顺序」项目      | 无                  | 否       | **AddIn 5002** ✅       |
| `CreatePages`     | 在当前项目建 5 页结构         | 无（先 CreateProject） | 是       | **AddIn 5002** ✅       |
| `DrawMainCircuit` | 主电路页插 3 个电机回路宏       | 无（先建页）             | 是       | **AddIn 5002** ✅       |
| `DrawPlcIO`       | PLC I/O 页插总览+DI+DO 宏 | 无（先建页）             | 是       | **AddIn 5002** ✅       |
| `DrawLadder`      | 梯形图页插急停/电源控制宏        | 无（先建页）             | 是       | **AddIn 5002** ✅       |

> **一次画完整套的顺序**：`CreateProject` → `CreatePages` → `DrawMainCircuit` → `DrawPlcIO` → `DrawLadder`。  
> 注意：CreatePages / 三个 Draw 都依赖“当前已打开的项目”，所以**必须先 CreateProject**。EPLAN 一旦重启，这个“当前项目”会清空，要重跑 CreateProject。

## 7. 怎么调用（复制即用）

### 7.1 PowerShell（本机测试最省事，推荐）

```powershell
# ① 先测 Web 服务活着没（不用 EPLAN）
$json = '{"action":"Ping","parameters":{"hello":"world"}}'
Invoke-RestMethod -Uri http://localhost:5000/api/eplan/execute -Method Post -ContentType "application/json" -Body $json

# ② 建物流传输项目（走 AddIn 5002，EPLAN 要开着）
$json = '{"action":"CreateProject","parameters":{}}'
Invoke-RestMethod -Uri http://localhost:5000/api/eplan/execute -Method Post -ContentType "application/json" -Body $json

# ③ 建 5 页
$json = '{"action":"CreatePages","parameters":{}}'
Invoke-RestMethod -Uri http://localhost:5000/api/eplan/execute -Method Post -ContentType "application/json" -Body $json

# ④ 画主电路（3 个电机回路）
$json = '{"action":"DrawMainCircuit","parameters":{}}'
Invoke-RestMethod -Uri http://localhost:5000/api/eplan/execute -Method Post -ContentType "application/json" -Body $json

# 打开已有工程（path 换成你的 .elk，注意用 / 不用 \）
$json = '{"action":"OpenProject","parameters":{"path":"D:/你的工程/demo.elk"}}'
Invoke-RestMethod -Uri http://localhost:5000/api/eplan/execute -Method Post -ContentType "application/json" -Body $json
```

### 7.2 Python（多数 AI Agent 用）

```python
import requests

def call_eplan(action: str, parameters: dict = None):
    url = "http://localhost:5000/api/eplan/execute"
    body = {"action": action, "parameters": parameters or {}}
    resp = requests.post(url, json=body, timeout=180)
    return resp.json()

print(call_eplan("Ping", {"hello": "world"}))
print(call_eplan("CreateProject"))
```

### 7.3 给其他 AI Agent 的“工具定义”（直接贴给另一个 AI）

把下面这段 JSON 注册成 Agent 的 function/tool，它就会自己决定何时调用你的 EPLAN：

```json
{
  "name": "eplan_execute",
  "description": "通过本机 API 操作电脑上的 EPLAN（自检/打开工程/建项目/建页/画电路）。仅本机 localhost:5000 可用。",
  "parameters": {
    "type": "object",
    "properties": {
      "action": {
        "type": "string",
        "enum": ["Ping", "OpenProject", "ExportPdf", "CreateProject", "CreatePages", "DrawMainCircuit", "DrawPlcIO", "DrawLadder"],
        "description": "Ping=自检；OpenProject=打开工程(需path)；CreateProject=新建物流项目；CreatePages=建5页(需先CreateProject)；DrawMainCircuit/DrawPlcIO/DrawLadder=画图(需先建页)；ExportPdf=导出(占位)。"
      },
      "parameters": {
        "type": "object",
        "description": "OpenProject 需含 path（.elk 路径，用 / 分隔）。其余动作一般传 {}。",
        "additionalProperties": { "type": "string" }
      }
    },
    "required": ["action"]
  }
}
```

## 8. 推荐的操作流程（照做不踩坑）

1. 打开 EPLAN（保持开着）。
2. 启动 Web 服务（第 4 节步骤 A），看到 `listening on 5000`。
3. 若 EPLAN 是刚开的，发一句 `CreateProject` 前，先确认 5002 已起（第 4 节步骤 B 的 Ping 验证）。
4. 依次发：`CreateProject` → `CreatePages` → `DrawMainCircuit` → `DrawPlcIO` → `DrawLadder`。
5. 回 EPLAN 窗口，应该能看到项目、页面、画好的电路。
6. 不干了就 `Ctrl+C` 关掉 Web 服务窗口；EPLAN 正常关。

## 10. 常见报错速查

| 现象 / 返回                            | 含义               | 怎么办                                                                                                                       |
| ---------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `success:true`                     | 成功               | 看 `message`                                                                                                               |
| `未知动作: xxx`                        | action 拼错        | 照第 6 节写，区分大小写                                                                                                             |
| 发请求报 404 / 连不上 5000                | Web 没起           | 回到第 4 节步骤 A，确认看到 `listening on 5000`                                                                                      |
| `address already in use`           | 5000 被占          | PowerShell 执行：`Stop-Process -Id (Get-NetTCPConnection -LocalPort 5000 -State Listen).OwningProcess -Force`，再 `dotnet run` |
| CreateProject 返回“无法连接 AddIn(5002)” | EPLAN 没加载插件      | 完全退出 EPLAN 再重开；再 Ping 5002 验证（第 4 节 B）                                                                                    |
| 画图动作报“项目未打开”                       | 没先 CreateProject | 先发 `CreateProject`；若 EPLAN 重启过，重发一次                                                                                       |
| OpenProject 无反应 / 超时               | 脚本桥接未被 EPLAN 信任  | EPLAN 首次跑脚本会弹“是否信任”，点允许/不再询问；否则走 CreateProject 系列（走 AddIn 更稳）                                                             |
| ExportPdf 返回“待实现”                  | 该动作还没写完          | 目前占位，等后续补全                                                                                                                |

## 11. 必读提醒（6 条）

1. **只在你本机有效**：`localhost` = 这台电脑，别的机器连不上。
2. **EPLAN 必须先能启动且开着**：AddIn（5002）靠 EPLAN 启动才上岗。
3. **路径用斜杠**：写 `D:/a/b.elk`，不要 `D:\a\b.elk`（反斜杠在 JSON 里是转义符，会出错）。
4. **动作不分大小写**：写 `ping` 或 `Ping` 都行。
5. **不会关你的 EPLAN**：`CloseAfterScript: false` 已设好。
6. **加新功能不用改接口**：以后所有新能力都是“加一个 action”，对 Agent 透明。

## 12. 可选：用 MCP 让 Claude / Cursor 自动调用

**先说结论：MCP 不是必需品。** 它只是个「转接头」，本身不干活。

| 你的用法                                                  | 要不要 MCP            |
| ----------------------------------------------------- | ------------------ |
| 用 PowerShell / curl 手动发命令                             | 不用，直接打 5000        |
| 用 AI Agent（如本机 DSH）来调                                 | 不用，Agent 自己能发 HTTP |
| 用 Claude Desktop / Cursor / Cline，想让它「自己判断何时该开 EPLAN」 | **要**，装 MCP 更省事    |

- 文件位置：`D:\默认存储空间\EPLAN\mcp\eplan_mcp_server.py`
- 它本质就是把第 5 节的 Web 接口包成「工具」，让支持 MCP 的客户端自动调用。
- **前置条件**：① EPLAN 已开、AddIn(5002) 已上岗；② Web 服务(5000) 已 `dotnet run`；③ Python 环境里已装 `mcp` 包。

### 12.1 端口必须两边一致（最容易踩的坑）

- Web 服务默认监听 **5000**（见 `Program.cs`、`appsettings.json` 的 `Eplan:ListenUrl`）。
- MCP 脚本也默认转发到 **5000**。
- 如果哪天 5000 被占用、你把服务改到了别的端口（例如 5001），**不用改脚本**，只要给 MCP 设一个环境变量：
  ```json
  "env": { "EPLAN_API_BASE": "http://127.0.0.1:5001" }

## 14. 实战总结（2026-10-04 一整天踩坑记录）★强烈建议先读这一节

这一天从「插件加载不上」一路查到了「工程级对象操控」，把 EPLAN 2.9 能走和不能走的路基本摸清了。结论按重要性排序：

### 14.1 ★ 插件热加载：不用重启 EPLAN（最大突破）

**问题**：EPLAN 2.9.4 **不会自动加载** `Bin\AddIns` 里的插件，每次重启 EPLAN，端口 5002 就没了。

**正解**：EPLAN 自带 **`EplanCommunicationServer`**（监听 TCP **49152**），外部程序可以通过它给**正在运行的** EPLAN 发送动作。

```powershell
# 一条命令把插件注入运行中的 EPLAN（无需重启）
D:\默认存储空间\EPLAN\EplanRemote\bin\Release\EplanRemote.exe ExecuteScript ScriptFile C:\Temp\EplanScripts\LoadAddIn.cs
```

看到 `ping -> True` 和 `Succeed=True`，再 Ping 一下 5002 有 `addin alive` 就成了。

**已经打包成双击即用的脚本**：

```
D:\默认存储空间\EPLAN\重新加载EPLAN插件.cmd
```

> 自查：`HKCU\Software\EPLAN\RemoteServer\<端口>` 里能看到 EPLAN 自己的进程号、版本和上次的启动命令行。

### 14.2 EPLAN 命令行**不认** `/Runscript`

试过 4 种写法，**全部失败**（EPLAN 把参数当成「操作名」，报 `S085021 无法找到操作`）：

```
/Runscript:"..."                        ❌
/ExecuteScript:"..."                    ❌
/ExecuteScript /ScriptFile:"..."        ❌
/ExecuteScript:ScriptFile:...           ❌
```

**结论**：命令行脚本这条路在 2.9.4 上走不通，**改用 14.1 的通信服务**。

### 14.3 页面幅面（图框）**API 改不动**，只能在界面上改

试过的所有办法，**全部被 EPLAN 忽略**：

| 办法 | 结果 |
| --- | --- |
| 事后改页面属性 `PAGE_FORMPLOT`（图框名称） | 写入成功、读回也对，但 `Page.Size` 不变 |
| 建页时在 `PagePropertyList` 里指定图框 | 同样被忽略 |
| 关掉工程重开再验 | 还是老的 `FN1_013` / A3 |
| 12 个图框名穷举（FN1_*、GB_A0~A4、NFPA、GOST） | **全部回退到 FN1_013** |
| 检查写保护 | `WriteProtected=False`，不是这个原因 |
| `Masterdata.UpdateProject()` 主数据同步 | 无变化 |
| `Masterdata.AddToProjectEx()` 添加图框 | 条目数不变（70→70） |

**根因**：这个工程的**主数据里没有任何图框记录**（70 条全是 `.fXX` 表格，一条 `.fn1` 都没有），所以 EPLAN 解析不了任何图框名，只能回退到平台内置的 `FN1_013`。

**唯一正确做法（GUI，30 秒）**：

```
左侧「页」导航器 → 展开工程 → 右键「页面」那一行（不是工程！）
  → 属性... (Ctrl+D) → 「图框名称」→ 选一个 → 确定
```

> ⚠️ 注意别右键到**工程**节点上，那样出来的是工程属性菜单，里面**没有图框**这一栏。

### 14.4 逻辑页的符号**不能缩放**

想把超大的图缩小塞进图框？**EPLAN 不允许**。API 文档原话：

> Symbol references on pages of type other than graphical cannot be scaled.

实测：686 个对象里 **563 个缩放失败**（只有线、文字这类图形元素被缩了），图被搞花。**只能还原。**

**结论**：幅面装不下时，唯一出路是**换更大的幅面**（A3 → A1 → A0）。A0 是标准里最大的（1189×841）。

### 14.5 宏框（MacroBox）怎么操控

| 操作 | 正确做法 | 坑 |
| --- | --- | --- |
| **移动** | `MacroBox.Group.Move(PointD)` | **Y 方向总会少走一个框高**，要补上 `boxH`；X 方向精确 |
| 改 `InsertionPoint` | 可写，但**改了图形不动** | 别用 |
| 改 `Location` | 只写属性（不给读） | 不推荐 |
| **查它框住了谁** | `MacroBox.ReferencedPlacements` | 这是精确的归属关系 |

```csharp
// 把宏框对齐到它框住的内容
double ox = boxMinX - contentMinX;
double oy = boxMinY - contentMinY;
double boxH = boxMaxY - boxMinY;
mb.Group.Move(new PointD(-ox, -oy + boxH));   // ← Y 要 +boxH
```

### 14.6 「孤儿对象」的精确定义

> **孤儿 = 不在任何宏框 `ReferencedPlacements` 列表里的对象。**

比「用坐标包含关系判断」准确得多（坐标法会把别的宏的内容也算进来）。
删除前务必**先备份**——孤儿里可能混着真实电气内容（端子、电缆、连接定义点）。

### 14.7 其它必须知道的坑

| 坑 | 真相 |
| --- | --- |
| 动作返回 `Succeed=False` | **未必真失败**！`XPrjActionProjectClose`、保存都返回 False 但确实生效了 |
| 工程开着时调 API | 报 `S063045 不能打开项目` —— **先让用户在 EPLAN 里关闭该工程**（EPLAN 主程序别关） |
| 工程关着时 `OpenProjects`/`GetProject` | 报 `S063110 不能生成 LockingStep 类别的对象` —— 用 `OpenProject(path, Exclusive)` |
| EPLAN 脚本里不能用 `ProjectManager` | 脚本环境**不引用 DataModel 程序集**（CS0234）。绕法：写个引用 DataModel 的**探针 DLL**，脚本用 `Assembly.Load(File.ReadAllBytes(...))` 加载它再反射调用 |
| 用 `Assembly.LoadFrom` 加载 AddIn | 同路径**会走缓存**，改了代码不重启 EPLAN 不生效 |
| PowerShell 脚本含中文 | 会被按 GBK 读 → 语法错误。**脚本一律写纯 ASCII** |
| `.elk` 文件格式 | UTF-16(带BOM)，内容两行：`<工程名>.edb` 和 `13.0` |
| 保存工程 | `Ctrl+S` 会弹「存储页?」，**回车**即确认（鼠标点击常常点不到） |
| 画出来的图没有块间连线 | `Insert` 接口**只插宏、不连线**；宏**内部**的连线是有的，块与块之间没有 |

### 14.8 本轮新增的工具（都在 `D:\默认存储空间\EPLAN\`）

| 文件 | 用途 |
| --- | --- |
| `重新加载EPLAN插件.cmd` | **双击**即可把插件注入运行中的 EPLAN，解决重启掉插件 |
| `EplanRemote\` | 通过 49152 通信服务远程执行任意 EPLAN 动作（`EplanRemote.exe <动作名> [参数名 参数值]`） |
| `EplanProbe\` | 探针 DLL，由脚本加载后执行：读工程结构、量尺寸、按区域/文字查对象、删孤儿、移动宏框、建页删页。**每次 `Assembly.Load(byte[])` 全新加载，改完即生效，不用重启 EPLAN** |

C:\Temp\probe_delete.txt    为 "yes" 时 junk 模式会真的删除
C:\Temp\probe_region.txt    区域查询矩形 xmin,ymin,xmax,ymax
C:\Temp\probe_text.txt      findtext 的搜索关键字
```
